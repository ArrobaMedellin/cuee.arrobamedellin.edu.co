# Inscripciones Sapiencia - Contexto para Modelos de IA

> Formulario público de inscripción para cursos de Sapiencia
> Versión: 0.1.0 | Última actualización: 30 de enero de 2026

## INFORMACIÓN GENERAL

**Nombre del Proyecto**: Inscripciones Sapiencia
**Stack Tecnológico**: Next.js 15.5.3, React 19.1.0, TypeScript 5, Tailwind CSS 4
**Propósito**: Aplicación web pública de formulario multi-paso para inscripción a cursos de capacitación de Sapiencia. Permite a ciudadanos de Medellín registrarse para acceder a programas educativos gratuitos.
**Backend**: Se conecta a `gestor-api` (NestJS - ver ../gestor-api/llm.txt)
**Estado**: ✅ Producción
**Organización**: Sapiencia - Medellín, Colombia

## CARACTERÍSTICAS PRINCIPALES

### Funcionalidades Clave

1. **Formulario Multi-Paso (7 secciones + 1 opcional)**:
- Sección 1: Información Personal
- Sección 2: Datos de Contacto y Ubicación
- Sección 2.1: Representante Legal (si es menor de 18 años)
- Sección 3: Dirección Completa
- Sección 4: Información de Dispositivos y Poblaciones Especiales
- Sección 5: Información de Discapacidad y Condición de Víctima
- Sección 6: Selección de Cursos
- Sección 7: Información Académica
- Summary: Resumen antes del envío

2. **Validación de Elegibilidad**:
- Edad mínima: 18 años
- Conexión con Medellín (al menos una): vivir, nacer o trabajar en Medellín
- Usuarios no elegibles: solo se guardan secciones 1-2

3. **Autocompletado Inteligente**:
- Búsqueda por número de documento
- Autocompleta secciones 1 y 2 si ya se registró antes
- Evita duplicados de inscripción

4. **Persistencia de Datos**:
- Guardado automático en localStorage vía Zustand
- Los datos persisten al recargar la página
- Sincronización en tiempo real

5. **Integración con API**:
- Envío de datos a gestor-api
- Verificación de duplicados por documento + período
- Creación o actualización según exista registro previo

6. **UX Mejorada**:
- Validación en tiempo real
- Mensajes de error descriptivos
- Indicadores de progreso
- Notificaciones (toasts) con Sonner
- Responsive design completo

## FLUJO DEL FORMULARIO

### Navegación Multi-Paso

El formulario está dividido en secciones con navegación secuencial:

```
Landing (/)
→ Redirect a /registration
→ Sección 1: Información Personal
↓ (si < 18 años)
→ Sección 2.1: Representante Legal
↓
→ Sección 2: Datos de Contacto
↓ VALIDACIÓN DE ELEGIBILIDAD
→ Si NO elegible:
→ Diálogo informativo
→ Envío parcial (solo secciones 1-2)
→ Redirect a /thanks
→ Si elegible:
→ Sección 3: Dirección
→ Sección 4: Dispositivos y Poblaciones
→ Sección 5: Discapacidad y Víctima
→ Sección 6: Selección de Cursos
→ Sección 7: Información Académica
→ Summary: Resumen completo
→ Envío completo
→ Redirect a /confirmation
```

### Secciones del Formulario

**Sección 1: Información Personal**
- Nombres y apellidos
- Tipo y número de documento
- País, departamento y ciudad de nacimiento
- Email
- **Búsqueda de inscripción previa** (ícono de lupa)

**Sección 2: Datos de Contacto y Ubicación**
- Fecha de nacimiento (cálculo automático de edad)
- País, departamento, ciudad de residencia
- Barrio, comuna (si es Medellín)
- Teléfono
- Género, orientación sexual, identidad de género
- **¿Trabaja en Medellín?** (para elegibilidad)

**Sección 2.1: Representante Legal** (condicional si < 18 años)
- Nombres y apellidos del representante
- Tipo y número de documento
- Parentesco
- Email y teléfono

**Sección 3: Dirección Completa**
- Tipo de vía (Calle, Carrera, Diagonal, etc.)
- Números y letras (9 campos para componer dirección)
- Dirección completa generada automáticamente

**Sección 4: Dispositivos y Poblaciones Especiales**
- Dispositivos disponibles (Laptop, Smartphone, Desktop, Tablet)
- Acceso a internet
- Pertenencia a población especial (LGBTIQ+, Desmovilizados, etc.)

**Sección 5: Discapacidad y Condición de Víctima**
- ¿Tiene discapacidad? (tipos: Visual, Auditiva, Física, Psicosocial, etc.)
- ¿Pertenece a grupo étnico? (Negro, Afrocolombiano, Indígena, etc.)
- ¿Es víctima del conflicto armado? (actos victimizantes)

**Sección 6: Selección de Cursos**
- Selección múltiple de cursos de interés
- ¿Cómo se enteró del programa?

**Sección 7: Información Académica**
- Nivel educativo alcanzado
- Institución educativa
- Año de graduación
- ¿Tiene pruebas ICFES Pro?

**Summary: Resumen**
- Visualización completa de todas las secciones
- Edición de cualquier sección
- Botón de envío final

## VALIDACIÓN DE ELEGIBILIDAD

### Requisitos para Proceso Completo

**Archivo**: `src/utils/eligibility.ts`

Para que un aplicante sea elegible para el proceso completo (secciones 3-7), debe cumplir:

1. **Edad mínima**: >= 18 años
2. **Conexión con Medellín** (AL MENOS UNA):
- Vive en Medellín (cityOfResidence = "Medellín")
- Nació en Medellín (bornCity = "Medellín")
- Trabaja en Medellín (worksInMedellin = true)

**Función de validación**:
```typescript
export function isEligibleForFullProcess(formData: RegistrationFormData): boolean {
const section2 = formData.section2
if (!section2) return false

// Verificar edad
const age = calculateAge(section2.birthDate)
if (age < 18) return false

// Verificar conexión con Medellín
const livesInMedellin = section2.cityOfResidence === 'Medellín'
const bornInMedellin = section2.bornCity === 'Medellín'
const worksInMedellin = section2.worksInMedellin === true

return livesInMedellin || bornInMedellin || worksInMedellin
}
```

### Flujo de No Elegibilidad

Si el usuario NO cumple los requisitos:

1. Al finalizar Sección 2, se muestra un diálogo informativo
2. Se explica por qué no es elegible
3. Se ofrece opción de guardar datos parciales
4. Se envían SOLO secciones 1 y 2 a la API
5. Redirect a página de agradecimiento `/thanks`

**Campos guardados en modo no elegible**:
- Toda la Sección 1 (información personal)
- Toda la Sección 2 (contacto y ubicación)
- Sección 2.1 si aplica (representante legal)

## AUTOCOMPLETADO POR DOCUMENTO

### Funcionalidad de Búsqueda

**Archivo**: `src/hooks/use-autofill-form.ts`

Permite buscar inscripciones previas por número de documento para evitar reescribir datos.

**Cómo funciona**:

1. Usuario ingresa número de documento en Sección 1
2. Click en ícono de lupa (o presiona Enter)
3. Hook ejecuta: `GET /applicants/document/:document`
4. Si encuentra registro:
- Toast de éxito
- **Autocompleta SOLO secciones 1 y 2**
- Usuario puede editar y continuar
5. Si no encuentra:
- Toast informativo
- Usuario continúa llenando manualmente

**Secciones autocompletadas**:
- ✅ Sección 1: Información personal completa
- ✅ Sección 2: Datos de contacto y ubicación
- ❌ Secciones 3-7: NO se autocompletan (usuario debe llenar)

**Razón**: Las secciones 3-7 pueden cambiar entre inscripciones (nueva dirección, nuevos cursos, etc.)

### Hook useAutofillForm

```typescript
export function useAutofillForm() {
const { setMultipleSections } = useFormStore()
const [isSearching, setIsSearching] = useState(false)

async function searchByDocument(documentNumber: string) {
if (!documentNumber) return

setIsSearching(true)
try {
const applicant = await apiService.findApplicantByDocument(documentNumber)

if (applicant) {
autofillFormData(applicant)
toast.success('¡Datos encontrados! El formulario se ha rellenado automáticamente')
} else {
toast.info('No se encontró ninguna inscripción previa con este documento')
}
} catch (error) {
toast.error('Error al buscar en la base de datos')
} finally {
setIsSearching(false)
}
}

return { searchByDocument, isSearching }
}
```

## PERSISTENCIA DE DATOS

### Guardado Automático con Zustand

**Archivo**: `src/stores/formStore.ts`

Todos los datos del formulario se guardan automáticamente en localStorage usando Zustand persist middleware.

**Configuración**:
```typescript
import { create } from 'zustand'
import { persist } from 'zustand/middleware'

export const useFormStore = create<FormStore>()(
persist(
(set) => ({
data: initialFormData,

setSectionData: (section, data) =>
set((state) => ({
data: {
...state.data,
[section]: data
}
})),

setMultipleSections: (data) =>
set((state) => ({
data: {
...state.data,
...data
}
})),

resetForm: () => set({ data: initialFormData })
}),
{
name: 'registration-form',
version: 1
}
)
)
```

**Guardado en tiempo real**:

Cada sección del formulario implementa un `useEffect` que observa cambios:

```typescript
// Ejemplo en Section1Form.tsx
useEffect(() => {
const subscription = form.watch((values) => {
if (values && Object.keys(values).length > 0) {
setSectionData('section1', values as Section1Form)
}
})
return () => subscription.unsubscribe()
}, [form, setSectionData])
```

**Ventajas**:
- Los datos persisten al recargar la página
- No se pierden datos si el usuario cierra accidentalmente
- Sincronización automática sin necesidad de botón "Guardar"

### Flujo de Envío

**Archivo**: `src/hooks/use-form-submission.ts`

1. **Validación**: Verifica que `documentNumber` esté presente
2. **Verificación de duplicados**:
- `findApplicantByDocument(document)`
- Busca si ya existe registro para ese documento en el período actual
3. **Transformación**:
- `mapFormDataToDto(formData)`
- Convierte datos del formulario a formato API
4. **Envío**:
- Si existe: `updateApplicant(id, data)` (PATCH)
- Si no existe: `createApplicant(data)` (POST)
5. **Notificación**:
- Toast de éxito o error
- Redirect a página de confirmación

**Hook useFormSubmission**:
```typescript
export function useFormSubmission() {
const [isSubmitting, setIsSubmitting] = useState(false)

async function submitForm(formData: RegistrationFormData) {
setIsSubmitting(true)

try {
const document = formData.section1?.documentNumber
if (!document) throw new Error('Número de documento requerido')

// Verificar si existe
const existing = await apiService.findApplicantByDocument(document)

// Mapear datos
const dto = mapFormDataToDto(formData)

// Crear o actualizar
if (existing) {
await apiService.updateApplicant(existing.id, dto)
toast.success('Tu inscripción ha sido actualizada correctamente')
} else {
await apiService.createApplicant(dto)
toast.success('¡Inscripción enviada exitosamente!')
}

router.push('/confirmation')
} catch (error) {
toast.error('Error al enviar la inscripción')
console.error(error)
} finally {
setIsSubmitting(false)
}
}

return { submitForm, isSubmitting }
}
```

// Obtener ID de API por valor de formulario
export function getCourseApiId(formValue: string): string | undefined {
return COURSE_MAPPINGS.find(c => c.value === formValue)?.apiId
}

// Obtener múltiples IDs
export function mapCourseValues(formValues: string[]): string[] {
return formValues
.map(getCourseApiId)
.filter(Boolean) as string[]
}

Para añadir o modificar cursos:

1. Editar `src/constants/courses.ts`
2. Añadir nuevo objeto al array `COURSE_MAPPINGS`
3. Asegurar que `apiId` coincida con el ID en la base de datos
4. El formulario automáticamente mostrará el nuevo curso

## HOOKS PERSONALIZADOS

### Hooks de Datos Geográficos

**useCountries** (`src/hooks/use-countries.ts`):
- Carga lista de países desde `data/countries.json`
- Retorna array de países con id y nombre

**useDepartments** (`src/hooks/use-departments.ts`):
- Carga departamentos de Colombia desde `data/departments.json`
- Retorna lista de departamentos

**useDepartmentsCities** (`src/hooks/use-departments-cities.ts`):
- Carga relación departamento → ciudades
- Filtro de ciudades por departamento seleccionado

**useCities** (`src/hooks/use-cities.ts`):
- Carga todas las ciudades de Colombia
- Permite filtrado por departamento

**useCommunes** (`src/hooks/use-communes.ts`):
- Carga comunas de Medellín
- Solo se usa si ciudad = Medellín

**useNeighborhoods** (`src/hooks/use-neighborhoods.ts`):
- Carga barrios de Medellín
- Filtrado por comuna si está disponible

### Hooks de Lógica de Negocio

**useAutofillForm** (`src/hooks/use-autofill-form.ts`):
- Búsqueda de inscripción previa por documento
- Autocompletado de secciones 1 y 2
- Manejo de estados de carga

**useFormSubmission** (`src/hooks/use-form-submission.ts`):
- Lógica completa de envío de formulario
- Verificación de duplicados
- Creación o actualización
- Manejo de errores

**useValidateSection** (`src/hooks/use-validate-section.ts`):
- Validación individual de secciones
- Previene avance si hay errores
- Integrado con React Hook Form

**useConditionalFields** (`src/hooks/use-conditional-fields.ts`):
- Manejo de campos condicionales
- Ejemplo: mostrar Sección 2.1 si edad < 18

## INTEGRACIÓN CON OTROS PROYECTOS

### Relación con gestor-api

Este proyecto (inscripciones-sapiencia) es el frontend público que alimenta datos a gestor-api:

**Flujo de datos**:
```
Usuario → inscripciones-sapiencia (formulario)
→ POST/PATCH /applicants
→ gestor-api (NestJS backend)
→ MySQL (tabla applicants)
→ gestor-app (admin dashboard)
```

**Endpoints consumidos de gestor-api**:
- `POST /api/applicants`: Crear aplicante
- `GET /api/applicants/document/:document`: Buscar por documento
- `PATCH /api/applicants/:id`: Actualizar aplicante

### Relación con gestor-app

- **inscripciones-sapiencia**: Formulario público (usuarios finales)
- **gestor-app**: Dashboard administrativo (staff de Sapiencia)

**Separación de responsabilidades**:
- Inscripciones: Captura de datos, validación, envío
- Gestor App: Visualización, gestión, reportes, sincronización con Moodle

## TROUBLESHOOTING COMÚN

### Datos no se guardan

**Solución**: Verificar que `form.watch()` está implementado en la sección.

Ver `FORM_STORAGE_FIX.md` para detalles.

### Usuario no puede continuar después de Sección 2

**Causa**: No cumple requisitos de elegibilidad.

**Solución**: Verificar edad (>= 18) y conexión con Medellín.

Ver `ELEGIBILIDAD_FIX.md` para detalles.

### Error al enviar formulario

**Posibles causas**:
- `NEXT_PUBLIC_API_URL` no configurada
- Backend no está corriendo
- Datos inválidos según schema

**Debug**:
```typescript
// Verificar en consola del navegador
console.log('API URL:', process.env.NEXT_PUBLIC_API_URL)
console.log('Form data:', formData)
```

### Autocompletado no funciona

**Verificar**:
- Número de documento es válido
- Endpoint `/applicants/document/:document` responde
- No hay errores de CORS

### Cursos no aparecen o IDs incorrectos

**Solución**: Actualizar `src/constants/courses.ts` con IDs reales de la API.
